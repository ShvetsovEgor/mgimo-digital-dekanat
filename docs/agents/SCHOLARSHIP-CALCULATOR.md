# Задача агенту: калькулятор стипендии

Бриф фичи. Выполнять, когда просят сделать калькулятор стипендии. Базовую сборку кабинета он не расширяет сам по себе.

Сделай в «Дедлайне» калькулятор академической стипендии. Это концепт конкурса, не официальный расчёт университета. Перед кодом прочитай AGENTS.md, docs/DESIGN.md, docs/SPEC.md, docs/agents/FRONTEND.md, server/src/contract.ts.

Задача экрана: студент видит, какая стипендия назначена сейчас, какая выходит по баллам текущего семестра, и сколько баллов не хватает до следующего уровня. Суммы и пороги вымышленные, но совпадают с сидом: академическая 2 500 ₽/мес, повышенная академическая 3 500 ₽/мес.

Регламент калькулятора (единственный, зашей его в server/src/lib/scholarship.ts):

- Договорное место (funded = contract) всегда даёт 0 ₽. Ползунки не влияют на итог.
- Бюджет: если хотя бы одна дисциплина текущего семестра ниже 70 — стипендии нет.
- Бюджет и все дисциплины ≥ 70, но хотя бы одна ниже 90 — «Академическая», 2 500 ₽/мес.
- Бюджет и все дисциплины ≥ 90 — «Повышенная академическая», 3 500 ₽/мес.
- Рейтинг дисциплины — целое 0…100. Пустого рейтинга в данных нет; если встретится null, считай его 0 и помечай «балл ещё не выставлен».
- Не добавляй социальную, президентскую и иные виды. Не меняй назначенную стипендию в сиде и в профиле.

Назначенная и прогнозная стипендия — разные факты. Профиль по-прежнему отдаёт строку scholarship. Калькулятор показывает обе: «Сейчас назначено» из профиля и «По баллам этого семестра» из расчёта. Они могут не совпасть.

API, только добавлением в server/src/contract.ts:
GET /api/me/scholarship для вошедшего студента, чужие данные не отдавать.
Ответ data:

- funded: 'budget' | 'contract'
- assigned: { title: string, amount: number } | null — из scholarship_json профиля
- rules: { academicMin: 70, increasedMin: 90, academicAmount: 2500, increasedAmount: 3500, disclaimer: string }
- disciplines: { id, title, rating }[] — текущие дисциплины из успеваемости, без контрольных точек
- result: { tier: 'none' | 'academic' | 'increased', title: string, amount: number, gaps: { id, title, rating, need, delta }[] }

gaps — только дисциплины, которых не хватает до ближайшего достижимого более высокого уровня. Если студент уже на повышенной, gaps пустой. Если стипендии нет, ближайший уровень — академическая (порог 70). Если академическая — ближайший уровень повышенная (порог 90). Для договора gaps пустой, в title объясни, что академическая стипендия на договорном месте не назначается.

Чистая функция evaluateScholarship(input) живёт в server/src/lib/scholarship.ts и покрыта server/tests/scholarship.test.ts. Проверь случаи: договор; бюджет и 69/90; бюджет и все ровно 70; бюджет и 89/90; бюджет и все 90; пустой список дисциплин; null-рейтинг. Клиент не хранит суммы и пороги: берёт rules из ответа и считает черновик той же формулой в web/src/lib/scholarship.ts. Формула короткая, суммы приходят с сервера.

Экран /scholarship, код в web/src/pages/ScholarshipPage.tsx и мелких компонентах (каждый файл ≤ 250 строк). Маршрут рядом с /progress. В нижнюю навигацию пункт не добавляй: там остаются пять вкладок. Входы:

- на /progress над сегментами карточка-ссылка «Калькулятор стипендии» с суммой прогноза;
- в профиле строка «Стипендия» ведёт на /scholarship;
- на главной одна карточка, если прогноз 0 при бюджете или прогноз ниже назначенной суммы: текст, чего не хватает, ссылка «Разобрать по предметам».

Интерфейс по docs/DESIGN.md: холст, белые карточки радиуса 12 с границей, без тени, акцент #9154EB, чернила #1C1B23, вторичный текст #6E6874. Индиго и золото не использовать. Числа — tabular-nums и русский формат «2 500 ₽/мес».

Состав экрана:

1. Заголовок «Калькулятор стипендии» и одна строка, что это учебный прогноз концепта, а не приказ о назначении.
2. Две цифры рядом: назначено и прогноз по текущим баллам.
3. Список дисциплин. У каждой название, текущий балл и ползунок 0…100 с шагом 1. Клавиатурный ввод того же числа. Пока ползунок двигают, прогноз и gaps пересчитываются локально, без запросов. Кнопка «Вернуть мои баллы» сбрасывает черновик к данным сервера.
4. Блок «Что поднять»: для каждого gap фраза вида «История России: 76 из 90, не хватает 14». Если gaps пуст и сумма > 0 — «Этого уровня баллы уже достигают».
5. Лестница из трёх ступеней (нет / академическая / повышенная) с порогом и суммой. Текущая ступень выделена акцентом, без отдельной плашки-меню.
6. Ссылка «Заказать справку о стипендии» на существующий заказ справки certificate-scholarship. Новый тип заявки не создавай.
7. Состояния: скелет, ошибка с «Повторить», пустой список дисциплин. На 360px без горизонтального скролла, цели ≥ 44 px, подписи ползунков доступны с клавиатуры.

Не трогай PDF, сессии, чужие роуты и поля существующих схем. После правки: npm test -w server и npm run build -w web. В браузере проверь трёх демо-студентов: a.ivanova (бюджет, назначена повышенная 3 500), m.karimova (бюджет, академическая 2 500), d.smirnov (договор, стипендии нет). У каждого сдвинь ползунок, сбрось баллы и открой экран с главной, из учёбы и из профиля.
