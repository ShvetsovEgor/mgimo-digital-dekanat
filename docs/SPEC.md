# SPEC — «Дедлайн», Цифровой деканат 2030

> Концепт личного кабинета студента МГИМО для конкурса VK Education.
> **Это неофициальный сервис**: прототип не подключён к системам университета, все данные вымышлены.

## 1. Проблема (что решает кабинет)

Учебная жизнь студента МГИМО распределена по десятку источников: расписание на портале,
рейтинговые ведомости в «Электронном деканате», справки — через заявление и офлайн-визит,
объявления — в Telegram, почте и в чате группы, изменения в расписании — в чате за минуту до пары.
Главная фрустрация — **неопределённость**: «я успеваю на “автомат”?», «когда будет готова справка?»,
«почему завтра нет пары?».

Кабинет «Дедлайн» собирает всё в одном месте и превращает неопределённость в понятные ответы.

## 2. Пользователи

| Роль | Что делает |
|---|---|
| Студент (бакалавриат) | смотрит расписание, успеваемость и рейтинг, заказывает документы, читает объявления, задаёт вопросы |
| Сотрудник деканата (секретарь) | видит входящие заявки своего деканата, меняет их статус, публикует объявления |

## 3. Ядро (обязательно, MVP)

### 3.1 Вход и профиль
- Вход по логину и паролю. Сессия серверная, cookie `HttpOnly`, срок 30 дней с продлением активности.
- Ошибки входа одинаковые для неизвестного логина и неверного пароля (без утечки, существует ли аккаунт).
- Ограничение попыток входа: 10 неудачных за 15 минут на пару IP+логин → блок на 15 минут (429).
- Тестовые аккаунты доступны с экрана входа в один тап (для жюри), подставляются в форму.
- Профиль: ФИО, факультет, направление, форма обучения, курс, группа, номер зачётки (маскированный), e-mail,
  куратор. Данные только чтения (кроме телефона и способа связи с деканатом).
- Смена пароля (текущий + новый), «Выйти на всех устройствах».

### 3.2 Расписание
- Экран «Сегодня»: пары дня с временем, аудиторией, корпусом, преподавателем, типом (лекция/семинар/языковая группа).
- Экран «Неделя»: переключение недель (чётная/нечётная), выбор дня на мобильном, карточки с изменениями.
- **Изменения и переносы** видны сразу: «Аудитория изменена», «Отменено», «Перенос с 16.11», «Добавлено».
  Изменение можно открыть и увидеть, кто и когда его опубликовал, и почему.
- Фильтры: только моя группа / с подгруппой / все.
- Счётчик «до пары N ч N мин», карточка следующей пары.

### 3.3 Успеваемость
- Дисциплины текущего семестра: накопительный рейтинг (%) из контрольных точек семестра,
  тип аттестации (зачёт / зачёт с оценкой / экзамен), «прогноз автоматического зачёта» (≥ 70% — «автомат» по регламенту).
- Прогресс-бар до порога 70% и до 100%.
- Итоговые результаты первого модуля (модульной сессии): рейтинг %, 5-балльная и ECTS-оценка по шкале МГИМО.
- Сводка: средний рейтинг, сумма зачётов, число «автоматов», академический рейтинг — место в потоке из N.
- Сессия/экзамены: даты, форма, оценки, «ещё не сдано».
- Оценки прошлых семестров (кратко).
- Шкала перевода оценок прямо в кабинете («как читать баллы»).

### 3.4 Заявки и справки
- Каталог сервисов с описанием, сроком и стоимостью:
  1. Справка об обучении (для военкомата / по месту требования) — бесплатно, 1 рабочий день;
  2. Справка о стипендии — бесплатно, 2 рабочих дня;
  3. Справка-вызов для визы/поездки — 3 рабочих дня;
  4. Академический отпуск по состоянию здоровья — заявление, до 3 рабочих дней;
  5. Индивидуальный учебный план — заявление, до 5 рабочих дней;
  6. Пересдача по дисциплине — до 2 дней;
  7. Запрос выписки из зачётной книжки / справки об успеваемости (PDF) — мгновенно.
- Форма заказа с понятными полями (где нужно — дата, причина, дисциплина). Валидация с понятными ошибками.
- Заявка получает номер `ЗВ-2030-000123` и **прогноз готовности** (с учётом нерабочих дней: пн–пт).
- Статус: «Ожидает проверки» → «В работе» → «Готово» (или «Отклонено» с причиной, «Отменено»).
- У готовой заявки — PDF: для справок — сам документ с QR, для остальных — электронное заявление с отметкой регистрации.
- PDF скачивает только владелец. QR ведёт на страницу проверки подписи (HMAC SHA-256), доступную без логина:
  показывает только «документ подлинный», номер и дату, без персональных данных.
- История заявок, фильтры по статусу.

### 3.5 Уведомления
- Лента событий студента: изменения расписания, новые оценки, статусы заявок, дедлайны, объявления деканата,
  личные сообщения от деканата.
- Непрочитанные: бейдж на колокольчике, кнопка «Прочитать всё», клик по уведомлению ведёт в нужный раздел.
- Встроенные напоминания о дедлайнах (ближайшие контрольные точки с датами), генерируются из данных.

## 4. Суперсилы (смелые идеи, выделяют работу)

1. **Лента «Сегодня»** — главный экран, который отвечает на вопрос «что у меня сегодня важно?»:
   следующая пара, ближайший дедлайн, что нужно сделать; всё в один экран без кликов.
2. **«Автомат»-прогноз** — прямо показывает: «до автоматического зачёта нужно ещё N баллов» (по регламенту МГИМО ≥ 70%).
3. **Умные напоминания о документах** — кабинет сам подсказывает: «Через 2 недели заканчивается отсрочка для военкомата — закажите справку-подтверждение» и предлагает заказать в один тап.
4. **Отслеживание заявки с прогнозом** — таймлайн «подана → в работе → готово» с прогнозируемой датой, без звонков в деканат.
5. **Проверка подлинности справки по QR** — цифровая подпись (HMAC) и публичная страница проверки.
6. **Помощник сценариев** — «Что мне сделать, чтобы получить …?» — каждая услуга имеет пошаговую инструкцию с кнопкой «Начать».
7. **Быстрый вопрос деканату** — студент задаёт вопрос прямо из кабинета, приходит ответ в уведомления.
8. **Ссылка на расписание для родителей** — нет (PII). Вместо этого «Расписание на неделю» → экспорт в календарь (.ics).
9. **Кабинет сотрудника** — секретарь деканата обрабатывает заявки, публикует объявления, меняет расписание.

## 5. Нефункциональные требования

- Мобильный first: 360 px, safe-area, sticky bottom tabs на мобильном, sidebar на десктопе.
- Быстро: первый экран < 1 с, API ответы < 100 мс на демо-данных, код-сплиттинг по разделам.
- Доступность: клавиатура, фокус, `aria-live` для тостов, контраст AA.
- Состояния: skeleton-загрузка, пустые состояния с действием, ошибки с «Повторить».
- Тёмная тема: автоматически по системе + переключатель.
- Защита: rate limit, Helmet-заголовки, CSP, CSRF через SameSite + проверку `Origin` для не-GET.
