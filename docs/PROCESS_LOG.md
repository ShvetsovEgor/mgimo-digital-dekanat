# Журнал работы с ИИ-ассистентами (сырые заметки процесса)

> Эти заметки потом перейдут в «Описание процесса создания» (PDF). Фиксируем всё по ходу:
> какие инструменты, какие промпты, какие результаты и какие ошибки ИИ пришлось исправлять.

## 0. Инструменты

| Инструмент | Роль в проекте |
|---|---|
| DeepSeek Harness (ассистент в IDE-чате, модель DeepSeek) | «дирижёр»: планирование, разведка, написание спецификаций для других агентов, интеграция, проверка, документация |
| Субагенты Harness (`subagent`) | отдельный агент-бэкендер и отдельный агент-фронтендер, работают параллельно по брифам из `docs/agents/` |
| Playwright-core + системный Chrome | автоскриншоты мобильных/десктопных экранов для отчёта и проверки 360 px |

| web-поиск + чтение страниц | разведка публичных ресурсов МГИМО (регламенты, шкала оценок, программа МО) |

## 1. Разведка (что реально устроено в МГИМО)

Промпты:
- «МГИМО кафедра регионоведения направления подготовки…»
- «МГИМО зачётная книжка баллы система оценивания»
- Запрос страниц `mgimo.ru/study/akadrating/`, `mgimo.ru/files/89/shkala_ECTS2.htm`, `mo.mgimo.ru/dip`.

Результаты (сохранены в `docs/research/`):
- **Шкала**: 90–100 % = «Отлично»/A; 82–89 % = «Хорошо»/B; 75–81 % = C; 67–74 % = «Удовлетворительно»/D; 60–66 % = E; < 60 % = F.
- **Правило «автоматического зачёта»**: итоговая оценка за работу в семестре (рейтинг) **≥ 70 %** → возможен «автомат»;
  ниже 70 % — традиционный зачёт, причём оценка за него не может превышать 70 %.
  Это и стало центральной механикой экрана «Учёба»: мы показываем, *сколько баллов не хватает до автомата*.
- **Программа МО «Дипломатия и политика зарубежных стран»** (41.03.01 «Зарубежное регионоведение»): реальные названия
  дисциплин для демо-данных (История России, Экономическая теория, Конституционное право и т.д.).
- Сайт МГИМО отдаёт страницы только после JS-проверки (`__jhash_` cookie) — один из «неудачных» шагов ИИ:
  он честно вычислил хэш, но сервер всё равно отдавал заглушку; зашли через прокси-ридер и публичные поддомены.

## 2. Постановка задачи агентам

Чтобы два ИИ-агента работали параллельно и не мешали друг другу, мы разделили проект по каталогам
и зафиксировали **контракт API до написания кода**: `server/src/contract.ts` (zod-схемы всех ответов).
Затем написали брифы:
- `docs/agents/BACKEND.md` — всё про сервер, модель данных, безопасность, PDF, сид, тесты;
- `docs/agents/FRONTEND.md` — экраны, UX-сценарии, дизайн, доступность, мок-режим;
- `docs/agents/SEED-DATA.md` — точные демо-данные трёх студентов и секретаря.

Промпт для субагента (дословно, сокращённо): «Ты — старший backend-разработчик… Твоя задача полностью описана
в docs/agents/BACKEND.md… Выполни задачу в точности по брифу… Не трогай web/. Доведи до зелёного npm test -w server».

## 3. Ход работ

### 3.1 Идея и эскиз (v0)
- Вручную сформулирована проблема: у студента МГИМО учебная жизнь разбросана по 6+ точкам входа
  (`docs/research/services-map.md`): личный кабинет, портал, расписание, «Электронный деканат»/академический
  рейтинг, справки через заявление, Telegram-каналы факультетов.
- Ассистент сгенерировал HTML-эскиз экрана входа (вместо макета в Figma — сразу в коде), снят скриншот
  `docs/assets/v0-login/v0-login.png`. На этой стадии была ошибка: эмодзи ✉ вместо логотипа —
  в финальной версии собственный SVG-знак «конверт с отломанным уголком» на индиго.
- Решение о «герое» продукта: **лента «Сегодня»** («что требует внимания сейчас»), а не очередной список разделов.

### 3.2 Контракт API до кода
- Чтобы два агента (backend и frontend) работали параллельно без конфликтов, сначала написан
  `server/src/contract.ts` — zod-схемы всех ответов (профиль, день, неделя, дисциплина, заявка, уведомление…).
- Первая версия контракта оказалась «тяжёлой» для фронта (вложенный профиль, даты ISO в полях подписи) —
  ассистент-«дирижёр» переписал её на плоские объекты с готовыми подписями («10:00», «пн, 20 ноя»),
  это ускорило frontend-агента и убрало дублирование форматирования.

### 3.3 Работа субагентов
- Промпт backend-субагенту (сокр.): «Ты — старший backend-разработчик… твоя задача в docs/agents/BACKEND.md…
  работай только в server/… доведи до зелёного npm test».
  Результат: Express 5 + SQLite (better-sqlite3), сессии, bcrypt, throttle, PDF-справка с QR, 30 тестов.
- Промпт frontend-субагенту (сокр.): «Ты — старший frontend-разработчик и UI-дизайнер… docs/agents/FRONTEND.md…
  работай только в web/… мобильный first 360 px». Результат: SPA на React 19 + Tailwind v4, 11 страниц,
  собственные UI-компоненты (Sheet, Toast, EmptyState…).
- После каждой итерации субагент отчитывался: что сделано, что упрощено, какие риски.

### 3.4 Ошибки ИИ и как их исправляли (важно для жюри)
| # | Проблема | Как заметили | Исправление |
|---|---|---|---|
| 1 | Риск-статусы не считались («в зоне риска: 0» при 42 % рейтинга) | скриншот экрана «Учёба» против ожиданий | переписана эвристика: «риск», если даже все несданные точки не доведут до 70 % или набрано < 60 % порога |
| 2 | «Средний рейтинг» 65 % при баллах 42–57 | ручная сверка с сидом | физкультура (порог 0) исключена из среднего; отдельно посчитано «автоматов» |
| 3 | Физкультура считалась «доступной для автомата», но с порогом 0  неактивна | тест API | порог физкультуры 60 (зачёт по посещаемости, но в интерфейсе — отдельная строка) |
| 4 | У готовой заявки подпись «Прогноз: сегодня» | нажатие на заявку | прогноз теперь абсолютной датой «16 ноя» |
| 5 | Неизвестный /api-путь отдавал 401/403 от guard'ов вместо 404 | тест `security.test.ts` | allowlist известных путей + динамические regex-ы, JSON-404 |
| 6 | 429 без заголовка Retry-After в одном из веток | тест троттлинга | Retry-After выставляется всегда |
| 7 | Студент при каждом переходе видел красную строку 403 в консоли | лог Playwright | для определения роли используется отдельный лёгкий запрос, ошибка гасится в `useRole` |
| 8 | На бесплатном хостинге сервис засыпает — демо-данные «застывают» в прошлом | ручная проверка идеи хостинга | авто-пересборка демо-данных через 20 ч + снимки экранов «как при старте» на экране входа |
| 9 | Пересборка на каждый запрос к /api/meta при DEMO_RESET_HOURS=0 — нагрузка до таймаутов браузера | тест reset-течения | «остывание» 10 минут между пересборками |
| 10 | На экране входа 4 карточки демо-аккаунтов + галерея снимков были громоздкими на 360 px | мобильный скриншот | галерея свёрнута в одну карточку «Смотреть 9 экранов» со Sheet |

### 3.5 Ручная работа
- Разведка публичных материалов МГИМО, сохранение источников в `docs/research/`.
- Постановка задачи агентам, ревью контракта, приёмка каждой страницы по чек-листу (360 px, 1440 px,
  пустые состояния, ошибки, клавиатура).
- Seed-данные: «сценарий» трёх студентов (сильный, в зоне риска, первокурсник) придуман вручную.
- Смоук-тесты API через curl, Playwright-скрипты для скриншотов (`scripts/`), проверки безопасности.
- Решения по хостингу и тексты для жюри.
