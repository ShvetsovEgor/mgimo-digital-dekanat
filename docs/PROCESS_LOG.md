## 1. Разведка (что реально устроено в МГИМО)

Промпты:
- «МГИМО кафедра регионоведения направления подготовки…»
- «МГИМО зачётная книжка баллы система оценивания»
- Запрос страниц `mgimo.ru/study/akadrating/`, `mgimo.ru/files/89/shkala_ECTS2.htm`, `mo.mgimo.ru/dip`.

Результаты (сохранены в `docs/research/`):
- **Шкала**: 90–100 % = «Отлично»/A; 82–89 % = «Хорошо»/B; 75–81 % = C; 67–74 % = «Удовлетворительно»/D; 60–66 % = E; < 60 % = F.
- **Правило «автоматического зачёта»**: итоговая оценка за работу в семестре (рейтинг) **≥ 70 %** → возможен «автомат»;
  ниже 70 % — традиционный зачёт, причём оценка за него не может превышать 70 %.
  Это и стало центральной механикой экрана «Учёба»: мы показываем, *сколько баллов не хватает до автомата*.
- **Программа МО «Дипломатия и политика зарубежных стран»** (41.03.01 «Зарубежное регионоведение»): реальные названия
  дисциплин для демо-данных (История России, Экономическая теория, Конституционное право и т.д.).
- Сайт МГИМО отдаёт страницы только после JS-проверки (`__jhash_` cookie) — один из «неудачных» шагов ИИ:
  он честно вычислил хэш, но сервер всё равно отдавал заглушку; зашли через прокси-ридер и публичные поддомены.

## 2. Постановка задачи агентам

Чтобы два ИИ-агента работали параллельно и не мешали друг другу, мы разделили проект по каталогам
и зафиксировали **контракт API до написания кода**: `server/src/contract.ts` (zod-схемы всех ответов).
Затем написали брифы:
- `docs/agents/BACKEND.md` — всё про сервер, модель данных, безопасность, PDF, сид, тесты;
- `docs/agents/FRONTEND.md` — экраны, UX-сценарии, дизайн, доступность, мок-режим;
- `docs/agents/SEED-DATA.md` — точные демо-данные трёх студентов и секретаря.

Промпт для субагента (дословно, сокращённо): «Ты — старший backend-разработчик… Твоя задача полностью описана
в docs/agents/BACKEND.md… Выполни задачу в точности по брифу… Не трогай web/. Доведи до зелёного npm test -w server».

## 3. Ход работ

### 3.1 Идея и эскиз (v0)
- Вручную сформулирована проблема: у студента МГИМО учебная жизнь разбросана по 6+ точкам входа
  (`docs/research/services-map.md`): личный кабинет, портал, расписание, «Электронный деканат»/академический
  рейтинг, справки через заявление, Telegram-каналы факультетов.
- Ассистент сгенерировал HTML-эскиз экрана входа (вместо макета в Figma — сразу в коде), снят скриншот
  `docs/assets/v0-login/v0-login.png`. На этой стадии была ошибка: эмодзи ✉ вместо логотипа —
  в финальной версии — собственный SVG-знак: две горизонтальные линии и «застёжка» между ними, цветом акцента.
- Решение о «герое» продукта: **лента «Сегодня»** («что требует внимания сейчас»), а не очередной список разделов.

### 3.2 Контракт API до кода
- Чтобы два агента (backend и frontend) работали параллельно без конфликтов, сначала написан
  `server/src/contract.ts` — zod-схемы всех ответов (профиль, день, неделя, дисциплина, заявка, уведомление…).
- Первая версия контракта оказалась «тяжёлой» для фронта (вложенный профиль, даты ISO в полях подписи) —
  ассистент-«дирижёр» переписал её на плоские объекты с готовыми подписями («10:00», «пн, 20 ноя»),
  это ускорило frontend-агента и убрало дублирование форматирования.

### 3.3 Работа субагентов
- Промпт backend-субагенту (сокр.): «Ты — старший backend-разработчик… твоя задача в docs/agents/BACKEND.md…
  работай только в server/… доведи до зелёного npm test».
  Результат: Express 5 + SQLite (better-sqlite3), сессии, bcrypt, throttle, PDF-справка с QR, 30 тестов.
- Промпт frontend-субагенту (сокр.): «Ты — старший frontend-разработчик и UI-дизайнер… docs/agents/FRONTEND.md…
  работай только в web/… мобильный first 360 px». Результат: SPA на React 19 + Tailwind v4, 11 страниц,
  собственные UI-компоненты (Sheet, Toast, EmptyState…).
- После каждой итерации субагент отчитывался: что сделано, что упрощено, какие риски.

### 3.4 Ошибки ИИ и как их исправляли (важно для жюри)
| # | Проблема | Как заметили | Исправление |
|---|---|---|---|
| 1 | Риск-статусы не считались («в зоне риска: 0» при 42 % рейтинга) | скриншот экрана «Учёба» против ожиданий | переписана эвристика: «риск», если даже все несданные точки не доведут до 70 % или набрано < 60 % порога |
| 2 | «Средний рейтинг» 65 % при баллах 42–57 | ручная сверка с сидом | физкультура (порог 0) исключена из среднего; отдельно посчитано «автоматов» |
| 3 | Физкультура считалась «доступной для автомата», но с порогом 0  неактивна | тест API | порог физкультуры 60 (зачёт по посещаемости, но в интерфейсе — отдельная строка) |
| 4 | У готовой заявки подпись «Прогноз: сегодня» | нажатие на заявку | прогноз теперь абсолютной датой «16 ноя» |
| 5 | Неизвестный /api-путь отдавал 401/403 от guard'ов вместо 404 | тест `security.test.ts` | allowlist известных путей + динамические regex-ы, JSON-404 |
| 6 | 429 без заголовка Retry-After в одном из веток | тест троттлинга | Retry-After выставляется всегда |
| 7 | Студент при каждом переходе видел красную строку 403 в консоли | лог Playwright | для определения роли используется отдельный лёгкий запрос, ошибка гасится в `useRole` |
| 8 | На бесплатном хостинге сервис засыпает — демо-данные «застывают» в прошлом | ручная проверка идеи хостинга | авто-пересборка демо-данных через 20 ч + снимки экранов «как при старте» на экране входа |
| 9 | Пересборка на каждый запрос к /api/meta при DEMO_RESET_HOURS=0 — нагрузка до таймаутов браузера | тест reset-течения | «остывание» 10 минут между пересборками |
| 10 | На экране входа 4 карточки демо-аккаунтов + галерея снимков были громоздкими на 360 px | мобильный скриншот | галерея свёрнута в одну карточку «Смотреть 9 экранов» со Sheet |
| 11 | Вторая вкладка «выкидывала» из первой: cookie одна на браузер | жалоба при демонстрации | сессия на вкладку: токен в `sessionStorage` + заголовок `X-Tab-Session`, `POST /api/auth/tab` для новой вкладки, файлы качаются через `fetch` с заголовком |

### 3.5 Ручная работа

### 3.6 Экран входа: виджет авторизации и сменяющиеся фоны
- Правая колонка переработана по `docs/agents/LOGIN-WIDGET.md`: карточка-виджет (радиус 26, паддинг 28–32),
  шапка «бренд + тема + RU», заголовок «Авторизация» с доменом `deadline.university`, поля с иконками,
  чекбокс «Оставаться в системе» (запоминается только логин), кнопка «Войти» с круглой иконкой.
- Демо-доступы для жюри — не отдельная карточка, а пункт «Вы вышли из аккаунтов» внутри формы:
  два аккаунта из `meta.accounts` (студент `a.ivanova` и деканат `dekanat`), вход в один клик.
  Это отступление от `LOGIN-WIDGET.md` (там просили отдельную карточку) — по решению заказчика экран стал компактнее.
- Левая колонка осталась с рассказом о кабинете; фон — три сгенерированных ИИ кадра кампуса
  (`static/` → сжатые копии в `web/public/backdrops/`, 200–290 КБ), кроссфейд раз в 9 с, при
  `prefers-reduced-motion` смена отключена. В тёмной теме кадр приглушается.
- Галерею скриншотов с экрана входа убрали (по брифу); API `/api/seed-context` остался доступным.
- Левая колонка вместо промо-текста показывает **карусель постов «канала кампуса»** (`CampusCarousel`):
  четыре поста от разных каналов (Деканат Live, Студсовет, Карьера и стажировки, Наука и проекты) —
  обложка, хэштег, заголовок, две строки текста, кликабельные реакции и стрелки. Автопереключение 7 с
  (фон меняется раз в 9 с, чтобы экран не «дёргался» целиком), пауза при наведении и после клика,
  переход fade+slide 350 мс. Свой логотип в левом верхнем углу убран — он уже есть в карточке авторизации;
  на мобильном карусель стоит под формой. Обложки — кадры сгенерированного кампуса (`web/public/covers`).

### 3.7 Профиль: чистка и баланс
- Убраны карточки «Контакты» (телефон и Telegram уже в шапке профиля — вместо карточки кнопка «Изменить»
  с карандашом, редактирование в модальном окне) и «Тема» (переключатель есть в шапке кабинета).
- Карточка «Учёба» оставила только уникальные поля: программа, семестр, форма обучения, № зачётки,
  стипендия (ссылка на калькулятор), общежитие, куратор — факультет, курс/группа и финансирование не дублируются.
- «Безопасность»: убрана серая плашка подтверждения (статус есть бейджем в шапке профиля) и техническая
  подпись про прототип у 2FA — осталось «Код из приложения при входе».
- Сайдбар расширен со 176 до 208 px: пункты меню больше не обрезаются троеточием; внешняя ссылка
  «Расписание МГИМО» переименована в «Сайт расписания» и помечена значком внешнего перехода.
- Сетка стала 2×2: слева профиль (с контактами) и «Учёба», справа «Деканат» и «Безопасность»; колонки
  выровнены по высоте, на 360 px — одна колонка без горизонтального скролла.

### 3.8 Главная: разгрузка дашборда
- Четыре крупные карточки быстрых действий заменены строкой пилюль «Справка · Калькулятор · Задать вопрос»
  (на 360 px переносятся на вторую строку без горизонтального скролла).
- Левая колонка — две карточки: «Что требует внимания» (только срочное) и «Сегодня в расписании»
  с живым бейджем в шапке («Идёт пара» / «Через N мин» / «Пары закончились») и таймлайном дня

  подсвечена. Отдельная плашка Live-статуса и строка «Завтра» внутри карточки заменили прежние блоки.
- Правая колонка — три карточки: «Стипендия» (две строки: назначено и прогноз, ссылка «Калькулятор»),

  (без вложенных рамок, срок только бейджем справа, сданные задачи скрыты).
- Блок «Последние события» и карточка «Быстрый вопрос» убраны: уведомления — в колокольчике шапки.
- Колонки выровнены по высоте, на 360 px — одна колонка без горизонтального скролла.

### 3.9 Проверка подлинности документа
- Ссылки «Проверка подлинности документа» вели на вымышленные токены (`/verify/demo`), поэтому страница
  всегда показывала «Документ не подтверждён». Теперь `/api/meta` отдаёт `demoDocument` — реально подписанный
  HMAC-токен первой готовой справки, и футер ведёт на настоящую проверку.
- У готовой заявки появился `verifyToken` (подпись номера и даты), карточка заявки открывает по нему страницу
  проверки; PDF по-прежнему содержит QR с той же ссылкой.
- `/verify` без токена стал рабочим экраном: объяснение, поле «ссылка или токен» (принимает ссылку из QR целиком)
  и кнопка с примером подлинной справки. Испорченный токен отклоняется.

### 3.10 Финальные правки по ревью
- Демо-база пересобрана: удалены дубли тестовых «Справок об обучении», созданные прогонами смоук-теста;
  у Анны снова ровно три заявки (готовая справка, справка о стипендии в работе, справка-вызов).
  Сид идемпотентен (DELETE + вставка), поэтому при перезапуске дублей не появляется; после `scripts/smoke.mjs`
  рекомендуется `npm run seed`, чтобы вернуть исходный демо-сценарий.
- «Учёба»: подпись `прошлый семестр: 84%` вместо безымянного «у вас 84%», бейдж «Критичный риск» с пояснением
  в подсказке, заголовок списка считает реально показанные дисциплины («Требуют внимания · 3»).
- Недельная сетка: у отменённой пары появился компактный красный бейдж «ОТМЕНЕНО».
- Профиль: контакты распределены по колонкам, e-mail и телефон в одну строку без разрыва; в сиде появились
  две «другие» сессии (ноутбук и телефон), поэтому счётчик активных сессий реалистичный — 3 с текущей.
- Язык: кнопка RU убрана из шапки кабинета, на экране входа она неактивна с подсказкой «EN — скоро».

### 3.11 Кабинет деканата
- Убрана горизонтальная полоса вкладок: разделы «Заявки / Вопросы / Объявления» живут в адресе (`?tab=`)
  и переключаются только из левого сайдбара; на мобильных — из нижней панели.
- Подсветка пунктов меню учитывает вкладку: акцентным цветом горит ровно один раздел (раньше все три
  совпадали по `/staff`). Рядом с «Вопросами» появился счётчик необработанных обращений.
- `/api/staff/stats` возвращал `pending/ready/rejected`, а карточки ждали `new/overdue/readyToday` — три
  показателя были пустыми. Запрос переписан: «Новые», «В работе», «Просрочены», «Готовы сегодня»,
  «Вопросы»; нули выводятся явно и приглушённо, на 360 px сетка 2×3 без обрезки подписей.
- ФИО сотрудника берётся из `/api/auth/me` (`Ольга Пахомова`, «Специалист деканата», инициалы `ОП`) —
  вместо заглушек `··` и `…`; для сотрудника скрыта ссылка «Профиль», аватар в шапке ведёт в кабинет.

### 3.12 Вопросы студентов как мессенджер
- Раздел «Вопросы» переделан в переписку: слева список чатов по студентам (аватар, имя, группа, превью
  последнего сообщения, время, счётчик непрочитанных), справа история — вопросы слева, ответы деканата
  справа акцентными пузырями с датой.
- Ответ отправляется из поля под перепиской в последний неотвеченный вопрос; когда всё отвечено,
  поле сменяется подсказкой. После отправки обновляются статистика и бейдж «Вопросы» в сайдбаре.
- На 360 px сначала список, при выборе — переписка на весь экран с кнопкой «Назад»; горизонтального
  скролла нет. Компоненты: `web/src/components/staff/StaffMessenger.tsx`, `ReplyComposer.tsx`.

## 4. Итоги проверки
- `npm test -w server`: 31 тест, 0 падений (аутентификация, IDOR, троттлинг, PDF, контракт).
- `scripts/smoke.mjs` (Playwright): 16 проверок живого кабинета на 360 px и 1440 px (вход, навигация, заявка, чужие данные).
